# AGENT.md

## 1. Project Objective

Build a complete, functional, installable **Relationship Manager PWA** using React, Vite, TypeScript, and Supabase.

The application helps users manage personal connections, track important events, and send personalized wishes generated by an n8n workflow.

Create a polished, modern, **dark-themed, mobile-first interface** with responsive layouts, intuitive navigation, subtle animations, and excellent usability.

Do not stop at planning or scaffolding. Implement the complete application, including database integration, CRUD operations, wish management, PWA support, seed data, documentation, and setup automation.

## 2. Technology Stack

- React with TypeScript
- Vite
- React Router
- Supabase PostgreSQL
- Supabase JavaScript client
- Tailwind CSS for styling
- Lucide React for icons
- A suitable Vite PWA plugin for installation and service-worker support

Use stable, mutually compatible package versions. Keep dependencies minimal and avoid unnecessary abstractions.

## 3. Core Features

### A. Dashboard

Display useful relationship insights, including:

- Total connections
- Upcoming events this month
- New wishes awaiting action
- Wishes already sent
- Upcoming events grouped by date
- Quick actions for adding connections and reviewing wishes

Calculate dashboard statistics from actual Supabase data. Handle empty datasets gracefully.

### B. Connections Management

Implement a complete connections directory with:

- List and view individual connections
- Add new connections
- Edit existing connections
- Delete connections with confirmation
- Search by name
- Filter by gender and relationship type
- Sort and paginate or progressively load records when appropriate

Each connection may contain:

- Full name
- Gender
- Profession
- Company
- Phone number
- WhatsApp number
- Email
- Relationship to the user
- Communication style
- Nicknames
- Hobbies
- Likes and dislikes
- Shared memories
- Additional notes

Use appropriate input controls for arrays and structured memories. Validate required fields and email/phone formats where applicable.

Support common relationship types, including friend, close friend, best friend, colleague, client, family member, and other. Allow custom relationship values.

### C. Wishes Management

Create two distinct views:

1. **New Wishes:** Generated wishes that have not been marked as sent.
2. **Sent Wishes:** Wishes that the user has marked as sent.

Fetch wishes from the existing Supabase `wishes` table. The n8n workflow independently generates messages and inserts them into this table. Do not recreate or replace that workflow.

Each wish should display the recipient, event name, relevant event date, and available message formats.

Include useful search, filtering, loading, empty, and error states.

### D. Wish Details and Sending

When a user opens a wish, display the available message variants:

**Email**

- Subject
- Body
- Copy controls
- Open the user's default email application with recipient, subject, and body prefilled using a `mailto:` link.

**Short Message**

- Display `short_wish`.
- Provide copy and SMS actions.
- Prefill the recipient's phone number and message where supported.

**Long Message**

- Display `long_wish`.
- Provide copy and WhatsApp actions.
- Open WhatsApp with the recipient's WhatsApp number and encoded message using a suitable `https://wa.me/` URL.

Use the recipient's email, phone, and WhatsApp number from the associated person record.

Account for missing contact details by disabling the relevant action and explaining why.

**Sending-state behavior:**

- Opening an external email, SMS, or WhatsApp application does not prove that the message was sent.
- Provide an explicit **Mark as Sent** action after the user has actually sent the message.
- Update `wishes.isSent` to `true` only after the user confirms.
- Move the wish from New Wishes to Sent Wishes after the database update succeeds.
- Show clear success and failure feedback.
- Prevent duplicate submissions and preserve the original wish content.

Do not claim that messages were automatically sent. This application only prepares messages and opens the relevant application.

## 4. Existing Supabase Schema

The following tables already exist. **Treat their names, columns, types, and relationships as the source of truth.**

Do not rename existing columns or introduce a parallel schema unnecessarily.

### `persons`

| Column              | Type        | Nullable |
| ------------------- | ----------- | -------- |
| person_id           | uuid        | No       |
| full_name           | text        | No       |
| gender              | text        | Yes      |
| profession          | text        | Yes      |
| company             | text        | Yes      |
| phone               | text        | Yes      |
| whatsapp_phone      | text        | Yes      |
| email               | text        | Yes      |
| relationship_to_me  | text        | Yes      |
| communication_style | text[]      | Yes      |
| nicknames           | text[]      | Yes      |
| hobbies             | text[]      | Yes      |
| likes               | text[]      | Yes      |
| dislikes            | text[]      | Yes      |
| memories            | jsonb       | Yes      |
| notes               | text[]      | Yes      |
| created_at          | timestamptz | Yes      |

### `events`

| Column      | Type        | Nullable |
| ----------- | ----------- | -------- |
| event_id    | uuid        | No       |
| event_name  | text        | No       |
| event_date  | date        | No       |
| isRecurring | boolean     | No       |
| created_at  | timestamptz | No       |
| person_id   | uuid        | Yes      |

### `wishes`

| Column     | Type        | Nullable |
| ---------- | ----------- | -------- |
| wish_id    | uuid        | No       |
| created_at | timestamptz | No       |
| mail_wish  | jsonb       | Yes      |
| short_wish | text        | Yes      |
| long_wish  | text        | Yes      |
| event_id   | uuid        | Yes      |
| person_id  | uuid        | Yes      |
| isSent     | boolean     | Yes      |

### Database integration rules

- Use the existing UUID primary keys and database-generated defaults.
- Use `person_id` to associate events and wishes with people.
- Use `event_id` to associate wishes with events.
- Use explicit TypeScript types for all database records.
- Handle nullable fields correctly.
- The `mail_wish` JSONB field should be treated as an object containing `subject` and `body`, matching the n8n output structure.
- Preserve the existing `isSent` column name and use the correct boolean value.
- Use appropriate joins or separate queries to retrieve associated person and event information.

Use an application-level type that combines a wish with its related person and event when required, rather than changing the database schema to accommodate UI needs.

## 5. Supabase Security and Configuration

Create a centralized `src/config/appConfig.ts` containing:

- Application name
- Application description
- Logo and asset paths
- Theme configuration
- Navigation labels
- Supported relationship types
- Other reusable global settings

Avoid duplicating these values throughout the application.

Read Supabase configuration from environment variables:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

Create a `.env.example` with placeholders only.

Never expose a Supabase service-role key or other privileged credentials in client-side code.

Document the need for appropriate Row Level Security policies. If authentication is not implemented, clearly document that the app must not be exposed publicly with unrestricted database access. Do not silently weaken existing security policies.

## 6. Design and UX Requirements

Build a professional, modern dark interface with:

- Responsive desktop and mobile layouts
- Mobile-friendly navigation and touch targets
- Consistent spacing, typography, and visual hierarchy
- Attractive cards, tables or lists, dialogs, and forms
- Clear visual distinction between New and Sent Wishes
- Accessible colors and readable contrast
- Subtle transitions and meaningful hover/focus states
- Confirmation dialogs for destructive actions
- Toast notifications or equivalent feedback
- Skeletons or loading indicators
- Helpful empty states and retryable error states

Avoid excessive gradients, clutter, unnecessary animation, and oversized dashboard cards.

Create reusable UI components rather than duplicating markup.

- Web app manifest

- Theme and background colors
- Suitable application icons
- Installability on supported browsers
- Service worker configuration
- Offline fallback for basic navigation where practical

Do not pretend that Supabase-backed data operations work offline unless proper offline synchronization is implemented.
